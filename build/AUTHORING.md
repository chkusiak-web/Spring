# Writing Jinan conversation scripts (天天)

天天 is an offline Mac app for learning Mandarin. In the Jinan map, the learner does **quests**: short typed conversations with one of 10 recurring characters. There is **no AI at runtime**. Each quest is a hand-written script, and the engine `app/talk.js` matches whatever the learner types against it.

The learner is an English speaker at the quest's HSK level. They type Chinese freely on a Mac Pinyin keyboard. Each objective is completed by one **step** of the script. The learner can usually do the steps in any order.

## Files
- Content and objectives (read-only): `app/data/jinan.js` (`window.JINAN`).
  - Each quest has `id`, `character`, `setting` and `objectives[{id, text}]`.
  - Character cards with personality and speech style are in the same file, under `characters`.
- Character lines: `app/data/jinan-scripts.js`. These cover greetings, self-introductions and "huh?" lines, and the engine says them for you. Do not edit this file.
- **Reference example: `app/data/scripts/baotu.js`.** Read it first and copy its style and shape exactly.
- You write `app/data/scripts/<districtId>.js`, one file per district:
  ```js
  /* 芙蓉街 Furong Street · HSK 1 · Food & snacks */
  Object.assign(window.JINAN_SCRIPTS.quests, {
    'furong-1': { ... }, ...
  });
  ```

## Quest script shape
```js
'furong-2': {   // 孙师傅 · Buy 油旋
  open:  [[zh, en], ...],      // scene opener; one is picked at random (after the character's own greeting)
  steps: [
    { obj: 'furong-2-1',          // exactly one step per objective id, listed in the objective order
      m:   ['油旋 什么', '这是什么'],          // patterns (see below)
      say: [[zh, en], [zh, en]],             // the character's reply when this step matches (1–2 variants)
      try: ['油旋是什么？', '这是什么？'],      // 2–3 example learner sentences; shown as suggestions after misses
      need: 'furong-2-3',          // optional: objective(s) that must be done first; '*' = all others first (use for goodbyes)
      card: { title: '价目表', rows: [['油旋', '3元/个'], ['豆浆', '2元']] }   // optional: a menu / price list / sign / timetable shown in chat
    },
  ],
  extra: [ { m: [...], say: [[zh, en]] } ],   // 1–3 optional answers to likely off-objective questions (no tick)
  fix:   [['三油旋', '三个油旋', 'Numbers need a measure word: 三个油旋.']],   // optional quest-specific known mistakes [wrong, right, short English note]
  done:  [[zh, en]],         // closing line once every objective is done
  words: [['油旋', 'yóuxuán', 'flaky scallion pastry']],   // 1–2 new words this quest teaches (added to the learner's review deck)
  later: [zh, en]            // a callback the character may say at the START of their next quest ("上次的油旋好吃吗？")
}
```

A line can carry options as a third element: `[zh, en, { ask }]`.
- `ask` makes the line a **yes/no question**, and the learner's yes or no picks the branch.
- Branch shape:
  ```js
  ask: { yes: [zh, en, { obj: 'furong-1-3' }], no: [zh, en] }
  ```
  `obj` is optional. When present, answering that branch ticks the objective, e.g. "要不要加鸡蛋？" → "要" ticks *Add an egg*.
- The step for that objective must still exist, so a learner who says it on their own also gets the tick.
- Use 1–2 forks per quest where it's natural, such as an upsell, "did you understand?" or an offer. This is the "mostly linear, with a few real forks" design.

## Patterns (`m`)
`m` is a list of alternatives, and the step matches if **any** alternative matches. Each alternative is a set of space-separated **terms**, and **all** terms must appear somewhere in the learner's sentence, in any order. The engine strips punctuation and spaces before matching.

| Term | Meaning |
|---|---|
| `油旋` | the substring must appear |
| `多少钱\|几块` | any one of these |
| `!不\|没` | none of these may appear |
| `@price` | macro |
| `{n}` | slot |

**Macros** (see `MACROS` in talk.js):

| Macro | Covers |
|---|---|
| `@hi` | 你好, 您好, 早上好, 奶奶好, 老师好, 师傅好… |
| `@thx` | thanks |
| `@bye` | 再见, 拜拜, 下次见, 明天见… |
| `@price` | 多少钱, 几块, 怎么卖, 一共… |
| `@want` | 要, 想要, 来, 买, 给我, 点… |
| `@pay` | 付钱, 微信, 支付宝, 现金, 扫码, 给你… |
| `@where` | where |
| `@when` | when |
| `@please` | 请问, 麻烦, 不好意思… |
| `@yes`, `@no` | yes / no |

**Slots** capture a value you can reuse in replies:

| Slot | Captures |
|---|---|
| `{n}` | a number (三, 3, 十五, 两) |
| `{time}` | a clock time (三点, 下午两点半) |
| `{color}` | a color |
| `{size}` | 大号, 中号, 小号, XL |
| `{drink}` | a drink |
| `{country}` | a country |
| `{day}` | 今天, 明天, 星期六, 周末… |
| `{spice}` | 不辣, 微辣, 中辣… |
| `{name}` | the learner's name after 我叫 / 我的名字是 |

- In `say` (zh **and** en), write `{n}`, `{color}` and so on. `{n*3}` multiplies, which is handy for totals, e.g. `'{n}个，一共{n*3}块！'`.
- Numbers render as Chinese numerals in zh (两 before a measure word) and as digits in en.
- `{slot|fallback}` gives a fallback when the slot is empty, e.g. `'{country|是吗}？'`.
- If a line uses a slot with no fallback, **every** pattern alternative of that step must capture that slot. The checker enforces this.
- Slots persist through the quest, so a later step can say `'这件{color|}的，三百块。'`.

**Writing good patterns**
- Cover the natural ways an HSK 1–3 learner would say it. Include synonyms (要/想要/来/给我), short forms and long forms. Think about what a beginner actually types.
- Keep patterns **specific to their step**. Avoid bare `好`, `是` or `要` as a whole pattern. They also match inside other words (你好 contains 好), and they steal other steps.
- Use `!` exclusions to keep steps apart, e.g. `'一张 !多少|几块'` so "多少钱一张" asks the price rather than ordering.
- Never rely on exact punctuation or word order.
- Greetings: `'@hi'`. Thanks: `'@thx'` with a `need`, so an early 谢谢 doesn't tick it. Goodbye: `'@bye'` with `need: '*'`.
- Before matching, the engine **corrects common mistakes** and then matches the corrected sentence:
  - measure words (三油旋 → 三个油旋, 一票 → 一张票)
  - 二 vs 两
  - 喝/吃 swaps
  - 多钱 → 多少钱
  - 是 + adjective
  - word order (付钱用手机, 我去X明天)
  - question word + 吗
  - pinyin typed instead of characters
  - English words (bag → 袋子)
  - homophone typos (在见 → 再见)

  So you don't have to pattern-match mistakes. Add `fix` entries only for mistakes specific to this quest's vocabulary.

## Writing the lines
- **Natural, standard Mandarin, Simplified characters, at the district's HSK level** (HSK 1 districts are very simple).
  - Short: 1–2 short sentences per line, like real speech at a counter.
  - At most ~2 new words per quest, and list them in `words` (pinyin with tone marks, short English gloss).
- Every `[zh, en]` needs an accurate, natural English translation; the learner clicks a bubble to see it.
- **Stay in character.** Use the character card's speech style and sprinkle in signature phrases (not every line).
  - 孙师傅 upsells (要不要加…？) and calls you 朋友.
  - 王奶奶 calls you 孩子 and asks if you've eaten.
  - 陈女士 is curt (下一位).
  - 小谢 says 哈哈 / 真的假的 / 走吧.
  - 老潘 says 我跟你说 / 堵死了.
  - 小苏 says 真的吗？/ 太酷了！
  - 林姐 is polished service language at work.
  - 白大夫 asks one calm question at a time.
  - 张老师 drops little history facts (你知道吗？).
  - 吕老师 praises (很好！) and models correct sentences.
- **Districts unlock in any order.** The `open` line must not assume an earlier quest happened; the engine adds a first-meeting self-introduction or a greeting for you. Don't put a greeting in `open` (the character's own greeting is already said); `open` sets up the scene.
- The reply in `say` should **move the conversation forward**: answer the learner and often invite the next natural objective, without listing objectives. Facts must stay consistent within a quest (prices, times, totals).
- `try` sentences must be correct, natural learner sentences that match **their own** step and trigger **no** correction. They are shown to the learner as suggestions, so make them good models. Keep them simple (HSK level) and use realistic learner content (name 大卫/安娜, country 美国/英国/加拿大).
- Add a `card` wherever a real person would show one: menus, price boards, timetables, train info, receipts, prescriptions.

## Checking
Run from `/home/claude/mandarin`:
```
node build/check_scripts.js furong                         # validate quests whose id starts with "furong"
node build/try.js furong-2 "师傅，油旋是什么？" "我要三油旋"   # play a quest by hand
```

**The checker must report 0 errors for your quests.** It verifies:
- every objective has exactly one step
- each `try` sentence ticks its own step (with all other objectives done) and needs no correction
- a full playthrough completes
- slot usage is consistent
- every line has a translation

Also fix cross-talk **warnings** where you can ("try X also ticks Y" means patterns overlap). Then play each quest by hand with a few realistic sentences, including a plausible beginner mistake, and make sure it feels right.

Do **not** edit `app/talk.js`, `app/data/jinan-scripts.js`, `app/data/scripts/baotu.js` or the checker. If the engine is missing something you need, work around it, and mention it in your final report.
